# 实验室运维

## 数据在哪里

本机开发数据默认在 `server/data/`；Docker 部署数据在 `lab-data` volume。其中包含 `onlyfunds.sqlite`、WAL 文件和 `uploads/`。媒体与数据库需作为一套备份。

## 一致性备份与恢复

最简单可靠的小型实验室备份方式是短暂停止 API，再复制整个数据目录：

```bash
mkdir -p output/backups
docker compose -f server/compose.yaml stop api
docker compose -f server/compose.yaml cp api:/data output/backups/lab-data
# 复制完成后恢复服务
docker compose -f server/compose.yaml start api
```

如 Compose 版本不支持从已停止容器复制，请通过 `docker cp` 使用实际容器 ID。确认备份目录含数据库和 `uploads/` 后，再备份服务器 `.env` 到受控的密码管理或加密备份系统。不要将账号数据库打包到客户端静态目录。

恢复时停止 API，保留旧数据快照，将整套备份写入相同数据卷并恢复 `node` 用户写权限，再启动并检查健康接口、账号登录、研究列表和视频播放。请在独立测试服务器演练恢复，不要第一次就覆盖生产数据。

## 邀请码与角色

学生和老板邀请码分开分发。修改邀请码并重启 API，只影响之后注册，不更改现有身份。当前没有 Web 管理员后台、邮箱验证或自助重置密码；邀请码应由管理员在受控渠道发给组员。

## 凭证泄露时

- 创作者密钥：在个人设置中撤销对应密钥，重新生成。
- 浏览器会话：当前标签页退出登录会撤销该会话。清除浏览器存储只删除本机副本，不会撤销其他设备会话。
- 需要管理员撤销全部会话时：停机备份后，在受控环境清空 `tokens` 表，再启动服务让成员重新登录。
- 轮换 `SESSION_SECRET` 会使旧签名媒体 URL 失效，但不会自动撤销数据库中的会话。

不要将 API 请求 Authorization 头、`.env`、令牌或完整私有研究内容输出到共享日志。

## 上传与容量

每个文件最多 100 MB。当前版本不转码、不提供自动病毒扫描或存储配额。原始视频应提前压缩为适合手机播放的 MP4（H.264/AAC）或 WebM。

未发布成功、删除动态后的媒体不会自动清除。定期检查数据卷容量。需要清理时先备份，对照 `media` 与 `posts.media_id/poster_id` 找出未引用文件，并确认没有正在进行的上传/发布，再由管理员实施；不要按文件时间盲目删除。

## 升级

1. 备份数据与配置，记录当前版本。
2. 在副本上运行新版本及检查流程。
3. 如发布涉及数据库版本升级，阅读对应迁移说明。
4. 执行 Compose 重建；确认健康、登录、发布和媒体播放。

当前初始版本只有模式版本 1，没有跨版本迁移器。后续模式变更必须提供显式迁移与回滚说明。

## 订阅账本升级

启动服务会将 SQLite schema 从 v1 自动迁移到 v3：增加学术资料、订阅快照、奖励菜单、账本期次、使用与兑现时间和通知。迁移使用事务，保留旧账号、动态和互动。升级前备份数据库与 uploads。旧订阅以升级时刻开始记新的免费期次；旧已兑现奖励保留状态，尚未记录的历史兑现时间显示“未记录”，不会捏造时间。升级后不要用旧镜像写入新数据库。
