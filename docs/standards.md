# 开发标准

## 版本与职责

根 `package.json` 是项目版本的权威来源。保持 `client/`、`server/`、`creator_toolchains/` 的清晰边界；文档和开发约定统一放在 `docs/`。`AGENTS.md` 只保存必须就近发现的路由与开发约束。

客户端始终是静态应用。不要为了某个页面引入服务端渲染、共享中央账号或代理层；服务器选择维持在个人设置。

## 代码与依赖

- 前端使用严格 TypeScript；函数和组件按真实职责拆分。
- 服务端的授权、所有权和输入限制不能只依赖前端隐藏按钮。
- 参数化 SQL；未知字段不直接写入 SQL、文件路径或请求 URL。
- React 默认文本转义，科研正文不直接注入原始 HTML。
- 不把令牌放入 URL 查询参数、日志或构建环境。媒体签名与会话密钥是不同用途。
- 修改依赖时同步 lockfile，使用 `npm ci` 重现；Remotion 各包版本必须一致。
- 示例研究必须标为演示；真实科研素材不可放入公共客户端或公共手册。

## 产品与移动端

保留熟悉的订阅式信息流操作。界面使用 OnlyFunds 自有文字和科研语义。所有按钮要有实际作用；尚未接入的能力明确说明。

主流程至少检查 375/390 px 手机与 1440 px 桌面。交互有可读标签，表单有错误反馈，弹窗可用 Escape 关闭并管理焦点；尊重减少动画设置。不要让主要操作只存在于桌面右侧栏。

加载、空数据、失联、会话过期、上传失败和权限不足都是正常产品状态。真实服务失联时不得无提示展示演示内容。

## 图片与演示媒体

头像默认使用最大 320 × 320 的 WebP；上传处理与演示导出都使用质量 78。科研演示配图使用 960 × 600 WebP，提供替代文本、预留尺寸、按需懒加载；视频点击后再加载。修改生成图时运行 `npm run demo:figures` 并检查总览，单张不得超过脚本的 55 KB 上限。导航、启动和 favicon 分别使用合适尺寸，避免直接加载 GPT-Image 原图。详见[演示媒体](demo-media.md)。

## 数据变更

新增数据结构应带显式模式版本、迁移步骤和备份恢复说明。当前数据库模式为 `user_version=3`，包含订阅计划、头像、礼物使用与账本；初始模式为 1。涉及角色、内容可见性、令牌范围或外部发布时，增加基于真实行为的 API 验证。

删除动态需保留已发放奖励的审计记录。媒体清理与数据库删除是独立操作，避免并发发布时误删文件。

## 验证要求

```bash
npm run check
python3 -m venv .venv-docs
.venv-docs/bin/pip install -r docs/requirements.txt
.venv-docs/bin/sphinx-build -W --keep-going -b html docs output/manual
```

`npm run check` 包括客户端与视频模板类型检查、API/创作者行为测试、生产客户端构建。

服务端测试覆盖登录、错误身份、用户隔离、发布密钥范围、媒体所有权和签名、订阅、收藏、评论、奖励、撤销与重启持久化。界面改动再通过真实浏览器检查相关流程，不需要为每个样式细节增加测试。

## 贡献交付

说明具体问题、修改后的行为、验证方式和当前限制；同步用户手册、API 与部署文档中受到影响的部分。只宣称已实际验证的结果，不把成功构建等同于已部署。
